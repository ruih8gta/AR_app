# てのひらサファリ 設計

## 構成

`android-compose-starter` の許可リストにあるひな形ファイルを空の `AR_app` に展開した独立プロジェクト。原本は変更していない。アプリIDは `com.ruih8gta.palmsafari`。

Kotlin / Jetpack Composeで操作画面を作り、`AndroidView` 内の `GLSurfaceView` で3DとARカメラを描画する。既存環境を利用するためUnityやエミュレーターを追加しない。

| 部品 | バージョン・役割 |
|---|---|
| Java / Gradle / AGP | 25 / 9.6.0 / 9.4.1。ひな形から継承 |
| Compose Plugin / BOM | 2.2.10 / 2026.02.01。ひな形から継承 |
| Android | compile/target 37、min 24 |
| ARCore | 1.57.0。ローカルな平面認識・追跡・アンカー |
| OpenGL ES | 2.0。カメラ背景、立体モデル、配置リング |
| デモ | Three.js 0.169.0。ブラウザ上の3Dプレビューのみ |

AGP 9の組み込みKotlinを使用。Gradleのworkersは2、並列ビルドは無効。公開用の署名・ストア提出設定は含まない。

## ARとライフサイクル

- 通常起動は3Dプレビュー。AR Optional、カメラ権限はAR開始時にのみ要求。
- AR開始説明 → 対応確認 → 必要ならARサービス導入 → カメラ許可 → セッション開始。
- ARCoreの外部カメラテクスチャを背景に描画。表示回転・アスペクト比は `setDisplayGeometry` と座標変換で反映。
- 上向き水平面内のヒット結果だけを採用し、`createAnchor()` で1体を固定。1倍の恐竜は約46cmの高さを想定（模型の定義単位 × 0.28m）。
- 置き直し・AR終了では古いアンカーをdetach。GL操作とヒットテストは描画スレッドで処理。
- 休止はGLスレッド停止後にARセッションをpause。復帰はセッションresume後に描画再開。
- Activity再生成・終了では配置を破棄。画面回転時は安全のためプレビューへ戻る。選択・サイズ・向き・動きはBundleで復元。
- 追跡喪失時はモデルを描かず案内。モデルの停止は直前のポーズを保持。バックグラウンド中の経過時間を動きに加算しない。

## モデル方針

2体とも外部ダウンロード素材を使わないオリジナルの簡易立体。球と円錐を関節ごとに組み合わせる。デモとAndroidで同じJSONを読み込み、同じ呼吸・頭・しっぽ・足ぶみの式を使用する。レンダラーと照明は異なるので見た目は完全一致しない。

高精細モデルへの移行は次段階。GLB/glTF読込・ボーンアニメーション対応のレンダラーを評価し、出典・利用条件・ポリゴン数・テクスチャ容量・歩行モーションを確認する。初版はGLBの任意読込に未対応。

## データと権限

独自サーバー、広告、解析、ログイン、撮影保存はなし。アプリはカメラ映像を保存・独自送信しない。ARCoreを使う旨とGoogleのプライバシーポリシーへのリンクを開始画面で表示する。Googleサービス自体のデータ処理は[公式説明](https://developers.google.com/ar/develop/privacy-requirements)に従う。Cloud AnchorsやGeospatialは利用しない。

モデルはAPK同梱。ARサービスの初回導入・更新・対応確認には通信が必要な場合があるため、完全オフライン保証はしない。デモはThree.jsをCDNから読み込む。

## 検証と次段階

PCで状態の上限、停止・復帰、脚の高さ、頂点・法線を検証する。ARの重ね合わせ、位置の安定性、追跡喪失・復帰、電池・発熱は実機確認が必要。記録は `docs/verification.md`。

次は機種の対応確認 → USB実機でプレビューとAR確認 → 見た目や操作を修正 → 希望する本番モデルの選定。撮影などの追加機能は要件に合意してから加える。
